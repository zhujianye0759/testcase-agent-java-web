## ADDED Requirements

### Requirement: REQ-TGV2-001 版本化已审核功能范围输入
系统 MUST 仅在已冻结 `workflow_version=2.0`、`input_version=2.0`、`artifact_version=2.0` 和版本化已审核功能范围时创建 V2 生成工作；范围必须按任务保存函数身份、名称、路径、描述及来源版本，且不得按材料类型或项目样本扩张。

#### Scenario: 创建 V2 任务
- **WHEN** 调用方提交有效的已审核功能范围和准入需求材料
- **THEN** 系统持久化精确版本与范围快照，并只为快照内的函数和文档规划工作

#### Scenario: 缺少已审核范围
- **WHEN** V2 创建请求未提供有效的已审核功能范围版本或范围为空
- **THEN** 系统在任何 KEE 调用和业务写入前失败关闭

### Requirement: REQ-TGV2-002 新任务仅调用 KEE V2 Skill
V2 工作流 MUST 只使用 `contract_version=2.0` 的 `requirement-fact-extraction` 与 `functional-testcase-design`，不得调用材料质量评审、功能提取/候选或功能对账旧 Skill/operation，也不得在 V2 失败时回退 V1。

#### Scenario: 正常 V2 编排
- **WHEN** 新任务进入需求事实和用例设计阶段
- **THEN** 调用记录只包含两个冻结 V2 Skill，旧 operation 调用次数为零

#### Scenario: KEE 不支持 V2
- **WHEN** KEE 返回 V2 不支持或固定合同错误
- **THEN** 系统按 HTTP 状态和 `error.details.type` 失败关闭且不调用旧 operation

### Requirement: REQ-TGV2-003 单文档完整事实请求
事实提取请求 MUST 恰好授权一个已准入需求材料文档，逐项发送与持久化 parsed unit 完全一致的 `unit_key`、`ordinal` 和 `content`；目标单元必须连续，context 与目标不重叠，原始 content 不得按 16 KiB 文本限制截断。

#### Scenario: 发送超长原始单元
- **WHEN** 持久化 parsed unit content 超过 16 KiB 且完整 V2 请求不超过配置上限
- **THEN** 系统原样序列化 content，不截断、不拼接并只授权当前文档

#### Scenario: 完整请求超限
- **WHEN** 序列化后的请求超过配置的 2–64 MiB 范围内上限或绝对 64 MiB
- **THEN** 系统在网络调用前失败关闭且不改变持久化事实

### Requirement: REQ-TGV2-004 事实和可测性反馈权威接收
Java MUST 验证事实响应的 function/window 回显、目标引用闭合、连续原文 quote、事实原子性、事实类型和反馈闭合；稳定事实键 MUST 由功能键、规范化事实类型与规范化事实文字确定，窗口内和跨窗口按键幂等合并并汇总精确引文。零事实与非阻断 `testability_observations` MUST 是合法终态。

#### Scenario: 合法事实窗口
- **WHEN** KEE 返回原子事实、目标单元连续引文和可测性反馈
- **THEN** 系统在同一事务保存稳定事实、引文、反馈、结果哈希和窗口终态

#### Scenario: 引用或原子性不闭合
- **WHEN** 任一事实引用当前目标和 context 之外的未知单元、quote 不连续命中或一个 statement 混合多个独立事实
- **THEN** 整个窗口零正式接收，其他已完成窗口保持不变

#### Scenario: 中英文复合义务
- **WHEN** 一个事实用逗号或英文 `and/or` 连接多个独立义务，即使整段在引文中连续出现
- **THEN** Java 将其判为非原子事实并整窗口零正式接收；条件从句中的连接词不单独触发误拒
- **AND** 无强终止符时，Java 只能依据重复义务标记、强谓词连接结构等通用高置信语法证据拒绝；字段集合、成对上下界和条件前缀必须先排除，不得依赖项目、业务动作或材料领域词表
- **AND** 自由文本无法提供确定语法证明时，Java 不得通过扩充领域动词表猜测语义边界；该类语义原子性仍由 KEE 的冻结输出合同承担，Java继续执行引用和直接依据的失败关闭校验

#### Scenario: 单一义务包含参数集合或比较条件
- **WHEN** 一个事实只表达一个可独立验证的行为或结果，但其输入、输出字段、边界条件或比较对象使用逗号、顿号、`和/与/及/或` 或英文 `and/or` 连接
- **THEN** Java 不得仅因出现连接字符就判为复合事实，并继续执行引文、直接依据和稳定身份校验
- **AND** 当连接结构两侧各自形成可独立验证的义务时仍须拒绝，不能把本场景作为跳过原子性门禁的通用白名单
- **AND** 条件前缀的识别必须基于语句边界，不得把“创建时间”等字段名中的字符当作条件结束符

#### Scenario: 零事实但有反馈
- **WHEN** KEE 对当前窗口返回零事实和合法可测性反馈
- **THEN** 系统记录完成窗口和反馈并继续其他窗口，不把材料质量当作技术失败

### Requirement: REQ-TGV2-005 测试点级三态用例生成
Java MUST 按一个持久化测试点调用 `functional-testcase-design`，并验证 `generated`、`pending_only`、`unable_to_generate` 与用例数量、case_status、missing_information、事实键和 evidence_keys 严格一致。

#### Scenario: 生成正式或待确认用例
- **WHEN** KEE 返回 generated 或 pending_only 且字段、步骤、证据与缺失信息闭合
- **THEN** 系统在单事务保存结果、用例、步骤、绑定和结果哈希

#### Scenario: 无法生成
- **WHEN** KEE 返回 unable_to_generate、零用例和非空缺失信息
- **THEN** 系统记录测试点终态与反馈，不伪造用例并继续其他测试点

#### Scenario: 三态矛盾
- **WHEN** outcome、用例状态、用例数量或 missing_information 不符合冻结矩阵
- **THEN** 当前测试点零正式接收且已完成测试点不回滚

#### Scenario: 两套材料分别覆盖待确认与无法生成链路
- **WHEN** 联合验收使用两套实质不同的测试材料，并分别在版本化已审核功能范围中冻结独立测试点：一项具有可执行步骤但仍有待确认条件，另一项确实缺少安全执行动作或可观察结果
- **THEN** 前者用于验证 KEE 实际选择的 `pending_only` 或 `unable_to_generate` 是否符合冻结三态矩阵，并仅在实际得到 `pending_only` 时证明待确认链路且不计入正式覆盖；不得把缺少量化条件硬编码成唯一结果
- **AND** 后者 MUST 形成 `unable_to_generate`、零用例和非空缺失信息
- **AND** 测试点身份和预期来源 MUST 是 Java 已冻结的已审核范围，不得临时修改 KEE JSON、让 KEE 猜测章节、按任务或材料名称特判
- **AND** 数据库、页面、第一张固定 Sheet“需求可测性反馈”和第二张“测试用例” MUST 使用同一已提交投影；`unable_to_generate` 不得伪造用例行，任何界面或导出不得泄露事实键、证据键、原始 KEE JSON、提示词或凭据

#### Scenario: 同名用例具有不同执行内容
- **WHEN** 两个候选名称、标题和引用相同，但初始化、输入、步骤、预期、评价、终止或采集内容不同
- **THEN** Java 的稳定用例身份包含完整可发布执行内容，并把二者保留为不同用例

### Requirement: REQ-TGV2-006 动态覆盖与非阻断局部继续
系统 MUST 根据已审核功能范围、持久化事实和动态测试点决定用例数量，不得使用固定 2N 或样本专用数量。一个函数、材料窗口或测试点失败时，其他独立范围 MUST 继续；只有经过验证的正式用例计入正式覆盖。

#### Scenario: 部分范围可生成
- **WHEN** 一部分测试点生成正式用例、另一部分只有待确认或无法生成结果
- **THEN** 系统保留全部真实终态，正式覆盖只计算正式用例且任务不会因需求表达不佳整体无制品

#### Scenario: 不同系统和规模
- **WHEN** 输入使用不同项目、材料格式、函数数量和窗口规模
- **THEN** 系统按冻结范围和协议处理，不依赖任务 ID、项目 ID、文档名、页数、章节或固定数量分支

### Requirement: REQ-TGV2-007 处理状态与覆盖结果分离
系统 MUST 分别持久化和投影处理状态与覆盖结果；技术工作结束、局部缺失和正式覆盖不足不得互相伪装，PARTIAL 不得显示为 COMPLETED。

#### Scenario: 技术完成但存在待确认
- **WHEN** 所有工作终态且仅部分测试点有正式用例
- **THEN** 处理状态反映工作已结束，覆盖结果独立显示正式、待确认和无法生成数量

#### Scenario: 技术失败
- **WHEN** 仍存在未完成或技术失败的工作
- **THEN** 处理状态不得显示完成，已提交正式覆盖数据保持可审计但不扩大范围

### Requirement: REQ-TGV2-008 事务幂等、并发与恢复
每个事实窗口和测试点结果 MUST 使用稳定工作身份、结果哈希和事务账本发布；同键同哈希重复接收幂等，异哈希拒绝，两个并发接收只有一个发布成功。失败或重启 MUST 只恢复未完成工作并保持零部分正式发布。

#### Scenario: 并发重复接收
- **WHEN** 两个执行者并发提交同一工作结果
- **THEN** 只有一个事务发布，另一个得到幂等成功或确定冲突且无重复业务行

#### Scenario: 事务中途失败
- **WHEN** 写入事实/用例链任一步发生数据库异常
- **THEN** 该工作所有正式行和账本一起回滚，后续可从同一冻结输入恢复

#### Scenario: 重启恢复
- **WHEN** 服务在部分工作完成后重启
- **THEN** 已完成工作不重调 KEE，未完成工作使用原范围和身份继续

### Requirement: REQ-TGV2-009 同源安全详情和双 Sheet Excel
详情 API、页面和 Excel MUST 从同一 task/artifact 的已提交结构化数据投影。页面使用中文读者安全字段，不显示原始 JSON、Markdown、内部枚举/键或凭据。V2 Excel MUST 恰好包含 `需求可测性反馈` 与 `测试用例` 两张 Sheet，第二张只含正式用例，并防止公式注入。V1 历史任务与历史制品 MUST 继续保留旧 Sheet `需求与功能清单审查发现`，不得静默重建或改名。

V2 详情中的可测性反馈、测试点和测试用例 MUST 使用独立的服务端显式分页；单页大小 MUST 有固定上限，单条用例的步骤和需求摘要 MUST 随该用例页一次读取，不得先加载全任务集合或按行执行级联查询；存在当前页结果时不得同时投影空状态。V1 历史详情 MUST 保持原有 JSON 形状。

考虑到单个测试点和单条用例均可接近 4 MiB，V2 测试点页和用例页 MUST 分别固定为一条；RUNNING/PENDING 阶段 MUST 隐藏仍会变化的结果页和待确认用例计数，仅保留阶段进度。终态详情的计数、当前页及关联子项 MUST 来自同一数据库一致性快照。

V2 Excel MUST 通过每类数据单次有序流式查询和有界工作簿窗口写入；MySQL 查询 MUST 设置驱动级流式游标，禁止驱动预取全量结果；步骤与需求摘要 MUST 在同一行聚合，禁止 OFFSET 重复扫描和按行级联查询。缺失信息 MUST 按规范文字稳定排序去重，不得继承 JSON 聚合或物理插入顺序。声明行数、实际写入行数和最终工作簿结构不一致时 MUST 失败关闭且不得发布制品。V1 已保存制品的读取格式保持不变。

生产行源 MUST 按来源身份严格递增并拒绝重复身份；数据库每页与 SXSSF 内存窗口 MUST 各保持一条大业务行。最终文件只可通过原子移动发布；文件系统不支持原子移动时 MUST 失败关闭并清理临时文件，禁止降级为普通移动。

#### Scenario: V2 详情与导出一致
- **WHEN** 用户查看 V2 任务详情并下载其 artifact
- **THEN** API、页面和 Excel 的正式/待确认/无法生成/反馈数量与关联一致，作者日期缺失时保持空值

#### Scenario: V2 大结果分页且 V1 形状不变
- **WHEN** V2 任务包含超过一页的可测性反馈、测试点或测试用例
- **THEN** API 分别返回三类集合的页码、页大小、总数和是否有下一页，并只读取当前用例页的步骤和需求摘要
- **AND** 查询 V1 历史任务时不新增 V2 分页字段

#### Scenario: 运行中结果仍在变化
- **WHEN** V2 任务处理状态为 PENDING 或 RUNNING
- **THEN** 详情继续显示阶段进度，但反馈、测试点、测试用例分页和待确认用例计数为空/零；进入终态后才按一致快照开放已提交结果

#### Scenario: 流式来源重复或原子发布不可用
- **WHEN** 数据库行源重复/乱序，或目标文件系统不支持原子移动
- **THEN** 导出失败关闭、删除临时文件且不发布可下载制品

#### Scenario: 公式样式输入
- **WHEN** 读者字段以 `=`, `+`, `-` 或 `@` 等公式前缀开始
- **THEN** Excel 将其作为安全文本写入且工作簿回读仍只有两张固定 Sheet

### Requirement: REQ-TGV2-010 历史 V1 只读兼容
系统 MUST 保留历史任务、V14-V19 数据和旧 artifact 的只读 API、页面与下载兼容；历史版本缺失时只可按 V1 投影，不得被 V2 协调器重新执行或自动迁移。

#### Scenario: 查看历史任务
- **WHEN** 用户读取版本字段为空或明确 V1 的历史任务
- **THEN** 系统返回原有详情和制品，不创建 V2 工作、不修改历史记录

#### Scenario: 不重跑已退役的 V1 生成门禁
- **WHEN** 回归验证历史 V1 任务兼容性
- **THEN** 系统仅验证原有详情、制品和公开写入口拒绝，不得重新执行已退役的功能清单/需求材料双向审核、功能冻结或固定 `2N` 生成流程
- **AND** 新 V2 任务继续按动态测试点和三态结果决定用例数量，不继承旧 golden fixture 的固定数量假设

#### Scenario: 新任务读取
- **WHEN** 用户读取 V2 任务
- **THEN** 系统只使用 V2 数据投影，不把旧候选/对账 staging 当作新流程门禁或覆盖结果

### Requirement: REQ-TGV2-011 V2 事实误拒的显式窄恢复
系统 MUST 只允许用户显式恢复满足完整零写入证明的 V2 事实原子性误拒；恢复 MUST 在一个事务中重新排队全部失败事实窗口、保留历史 attempt，并将因“尚无正式事实”生成的旧 `unable_to_generate` 设计工作标记为历史结果，使其退出当前详情、覆盖和 Excel 投影。系统不得把 `FACT_ATOMICITY_INVALID` 加入通用自动重试白名单，也不得按任务、项目、材料名称或固定函数数量特判。

#### Scenario: 恢复全部原子性误拒窗口
- **WHEN** V2 任务处于 PARTIAL/FAILED，全部未完成工作都是零写入的 `REQUIREMENT_FACT_EXTRACTION_V2`，最新 attempt 均为 `business_validation_failed / FACT_ATOMICITY_INVALID / $.requirement_facts[n].statement`，且已完成下游仅为每个已审核功能一个“缺少正式事实”的 `unable_to_generate` 结果
- **THEN** 一次显式 retry 在同一事务重新排队全部失败事实窗口、把对应旧下游工作标记为 `SUPERSEDED`、保留旧 attempt/结果哈希和业务行作为审计历史，并清除任务旧制品坐标后恢复同一任务
- **AND** 下一次协调只为重新排队的事实窗口创建新 attempt；事实完成后根据新事实规划新的测试点，不把 `SUPERSEDED` 结果计入当前处理、覆盖、页面或 Excel
- **AND** 若重新排队的事实仍未能正式接收，协调器可在再次证明同一稳定缺失事实结果的身份、结果哈希和完整业务投影后，将其从 `SUPERSEDED` 恢复为当前 `COMPLETED`；不得重跑 KEE 或通用激活其他历史工作

#### Scenario: 保留已验证的无法生成原因
- **WHEN** 缺少正式事实的固定测试点已由 V2 用例结果校验器接收为 `unable_to_generate`，且模型返回的非空 `missing_information` 比规划输入的提示更具体
- **THEN** 恢复资格和后续重激活 MUST 以已持久化结果重算结果哈希并复验 `unable_to_generate` 业务矩阵，不得机械要求输出原因逐项等于输入提示
- **AND** 空原因、结果哈希不一致、正式/待确认用例、绑定或其他额外业务行仍必须失败关闭

#### Scenario: 近似状态失败关闭
- **WHEN** 存在已接受事实/反馈/事实发布账本、正式或待确认用例、非 fallback 下游结果、accepted hash、活动租约/attempt/slot、其他未完成工作、非安全错误码或不完整制品坐标中的任一情况
- **THEN** `canRetry=false` 且 retry 事务不改变 task、work、attempt、业务行或制品坐标
- **AND** 缺失事实 fallback 的工作集合、测试点、结果和发布账本必须形成精确闭集，任一多余行、字段语义漂移或账本哈希不一致均失败关闭

#### Scenario: 并发恢复与事务回滚
- **WHEN** 两个用户并发触发同一显式恢复，或恢复中任一预期行数/约束检查失败
- **THEN** 任务行锁保证最多一个请求成功，失败请求或中途异常整体回滚，不出现部分 requeue 或部分 supersede

### Requirement: REQ-TGV2-012 事实陈述与直接依据的保守语义闭合
Java MUST 将 `statement` 视为原子事实的读者可读语义描述，将 `source_quotes[].quote` 视为连续原文依据；不得要求 `statement` 必须逐字成为完整解析单元或引文的子串。直接依据校验 MUST 在单条已授权、已连续命中的引文内证明事实语义，没有确定证明时失败关闭，不得跨引文或跨材料拼接。

#### Scenario: 同一义务的受控压缩
- **WHEN** 原子事实只省略原文中的通用系统主语或其指示词、连接成分或重复修饰，或重排同一结构明确的字段集合，且角色、关系参与者、条件、范围控制与当前状态修饰、数字、单位、字面值、英文标识和业务动作均可在同一连续引文中得到证明
- **THEN** Java 接收该事实并继续执行原子性、稳定身份和事务发布校验，不因陈述不是原文逐字子串而误拒
- **AND** 字段集合的子集或重排只可由逐成员带引号的字段标签或逐成员布尔字段语法证明；成对引号内部的逗号、顿号或 `and/or` 属于字段标签本身，不得再次拆分；枚举标点只证明边界，不能把普通短语证明成字段，且不得按字数、有限动词词尾或固定业务词表推断成员身份

#### Scenario: 规范英文缩写
- **WHEN** 事实使用的英文缩写可由同一引文中连续英文词组的首字母唯一展开，其他动作和结果仍由该引文支持
- **THEN** Java 可以把缩写视为同一依据，不依赖项目、材料名称或固定业务词表

#### Scenario: 新增业务含义失败关闭
- **WHEN** 陈述增加引文未支持的角色、动作、状态、阈值、数字、单位、字面值或英文标识，或只能拼接多条引文才成立
- **THEN** 当前窗口以 `FACT_DIRECT_EVIDENCE_UNSUPPORTED` 整体零接收；连续引文、授权范围和其他已完成窗口保持不变
- **AND** 引文中的前置或尾置条件、范围限定及“当前”等业务状态修饰不得当作普通主语或连接成分删除；逗号后的独立动作不得伪装成字段集合成员

#### Scenario: 直接依据拒绝只保存安全规则诊断
- **WHEN** 当前事实的全部独立引文均不能证明陈述，Java 将窗口判为 `FACT_DIRECT_EVIDENCE_UNSUPPORTED`
- **THEN** attempt、work 和 task 的内部失败详情 MUST 只保存稳定、有限的规则原因集合，并至少区分字面值不闭合、从句数量不符、绑定前缀丢失、内部省略不安全、边界省略不安全、控制词不闭合及词序或新增词元
- **AND** 多引文失败原因 MUST 按固定枚举顺序去重，任一引文通过时不得产生拒绝诊断；诊断枚举不得作为自动放宽或自动重试依据
- **AND** 失败详情不得保存 `statement`、quote、evidence key、提示词、原始 JSON、材料正文、凭据、文本哈希或内部对象身份；详情 API、页面、Excel 和普通日志只显示原有固定公共说明，不显示规则枚举

#### Scenario: 多个动作共享一个义务词
- **WHEN** 一个陈述以同一个 `必须/must` 等义务词同时支配两个可独立执行、独立失败的动作，而第二个动作没有重复义务词
- **THEN** Java 仍将其判为复合事实并整窗口零接收；字段集合、成对范围约束、同一字段的字面值映射和条件从句不因此误拒

#### Scenario: 直接依据误拒的同任务窄恢复
- **WHEN** V2 任务仅有一个或多个 `FACT_DIRECT_EVIDENCE_UNSUPPORTED` 事实窗口零写入失败，失败功能只产生了经验证的缺事实回退，而其他功能已经完成事实或用例发布
- **THEN** 显式恢复仅重排失败事实窗口并使这些功能对应的当前回退退出投影；其他功能的已完成 work、事实、用例、attempt 和发布记录保持不变，任一受影响功能存在正式下游结果或闭集外业务行时失败关闭
- **AND** 同一受影响功能的其他事实窗口若已原子完成但产出零事实、零反馈，必须保留其 accepted hash 与发布账本并跳过重跑
- **AND** 任一声称已完成的事实或用例工作必须具有唯一成功 attempt、匹配 accepted hash 的已验证公开结果和精确业务投影；缺少可复演结果、三态结果、步骤、绑定或存在闭集外业务行时恢复资格必须失败关闭
- **AND** 全部已完成事实窗口重放所得的事实键和事实引文并集必须与任务级持久化集合精确相等；任一额外事实、额外引文、空白或未冻结功能身份均失败关闭
- **AND** V2 结构化任务必须在锁内选择 V2 专用恢复分支；即使同一任务混入可重试的旧批次行，也不得先改变旧批次或绕过 V2 闭集校验
- **AND** 大规模恢复按固定事实工作、解析单元和用例工作批次读取；原始解析单元正文与 V23 回放 JSON 只在当前批次内存活，快照只保留任务级哈希/闭合结论，不得把整任务正文或回放结果同时缓存在内存
- **AND** 锁内门禁必须使用能看到等待期间已提交业务行的当前读；并发插入任一事实、反馈、用例、步骤、绑定或发布坐标后，恢复资格必须失败关闭
