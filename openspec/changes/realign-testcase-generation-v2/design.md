## Context

当前 Java `ALL` 结构化工作流按“材料质量评审 → 功能提取/候选 → 功能范围核对 → 测试点 → 测试用例”执行，并把前置评审或对账失败视为生成失败。新的跨服务职责把测试准入审核和完整需求质量评审移出生成系统；Java 只消费版本化已审核功能范围，从正式需求材料提取原子事实，并按测试点尽力生成正式或待确认用例。

KEE version 2 第一阶段只冻结两个 Skill：`requirement-fact-extraction` 与 `functional-testcase-design`。KEE 负责结构、范围和原始解析单元一致性；Java 负责业务闭合、稳定身份、去重、事务、状态、页面和 Excel。未冻结字段不得出现在 Java 请求、响应或持久化假设中。

现有工作树保留 V1 历史任务、V14-V19 表和旧制品读取。新路径必须并存迁移，不能改写历史数据，也不能在 V2 失败时回退旧 operation。

## Goals / Non-Goals

**Goals:**

- 为新任务冻结 `2.0` 工作流、输入和制品版本，以及版本化已审核功能范围。
- 精确实现两个 KEE V2 DTO、容量边界和 Java 业务接收校验。
- 按函数/材料窗口/测试点局部继续；材料不规范时形成非阻断反馈和待确认结果。
- 用一次向前迁移持久化 V2 输入、事实、反馈、生成结果和幂等账本，确保零部分正式发布。
- API、页面和两 Sheet Excel 从同一已提交记录投影，并保留旧任务只读兼容。

**Non-Goals:**

- 不实现测试准入材料审核、功能清单与需求材料遗漏/冲突核对或完整需求质量评审。
- 不新增或猜测 KEE 未冻结字段，不维护模型输出上限表，不设置固定输出 token 上限。
- 不删除旧 DTO、旧表或历史制品，不恢复旧任务，不部署或运行真实业务任务。
- 不为梅州样本、固定文档格式、页数、章节、功能数或固定用例倍率增加分支。

## Decisions

### 1. 新旧工作流按持久化版本分派

新建任务必须显式冻结 `workflow_version=2.0`、`input_version=2.0`、`artifact_version=2.0` 和已审核功能范围版本。协调器按版本选择独立 V2 路径；历史记录缺少这些字段时按 V1 只读投影。V2 适配失败直接失败关闭，不调用任何旧 Skill 或 operation。

选择版本分派而不是修改旧协调器步骤，是为了隔离历史恢复语义并提供“新调用零旧 operation 引用”的可审计证据。

### 2. V2 DTO 与通用 isolated-Skill 外壳分离

为两个 V2 Skill 建立专用不可变 DTO 和明确序列化字段。通用外壳只携带冻结合同列出的公共字段。事实提取每次只授权一个已准入需求材料文档；测试设计只携带 Java 已接收的事实和一个测试点。`units.content` 保持数据库原值，不截断、不套用普通 16 KiB 文本限制。

材料读取适配器必须逐页释放正文和游标，不得按文档规模保留全部单元键或游标集合；任务数据库以 `(task, document, unit)` 唯一键、连续 ordinal 和最终总数闭合承担跨页身份门禁。端口的默认分页实现必须失败关闭，禁止静默调用全量读取。

HTTP 客户端只根据状态码和 `error.details.type` 分类，V2 请求限制默认 16 MiB、配置范围 2–64 MiB且绝对不超过 64 MiB，响应限制 4 MiB；不读取可变 message 决定恢复策略。

### 3. Java 在窗口事务中权威接收事实与反馈

接收前逐项核验 function/window 回显、引用存在且归属目标单元、quote 连续命中、事实原子性和反馈闭合。事实稳定键由功能键、规范化事实类型和规范化事实文字生成；同一事实在不同窗口出现时按稳定键合并精确引文并去重。一个窗口的全部事实、引文、反馈、结果哈希和账本在同一事务提交，任一失败则该窗口零正式写入。

事实原子性同时识别中文和英文连接结构；逗号分隔、双方重复义务词或多个动作共享一个义务词的独立义务，不能因原文连续而被误收。条件从句只作为同一事实的触发条件，不把条件中的连接词误判为多事实；完整条件原句可以包含普通名词，只有删除条件边界标点时才要求语法能够无歧义证明该边界。显式恢复只替换已证明为零写入的事实误拒窗口；对缺少正式事实而形成的 `unable_to_generate` 历史结果，恢复资格按当前 V2 用例结果合同复验其非空缺失信息并重算结果哈希，而不把规划输入的一条提示误当成模型输出的固定答案。

KEE 返回零事实是合法结果；Java仍记录窗口终态和 testability feedback。反馈不阻断其他窗口和后续可生成范围。

事实的直接依据不再用“整句陈述必须逐字出现在完整解析单元”代替业务语义。Java 先保持现有 evidence key 授权与连续 quote 校验，再在每条 quote 内独立验证陈述的保守语义闭合：允许删除经义务标记证明的通用系统主语或其指示词、连接成分或重复修饰，以及由连续英文词组首字母形成的规范缩写；保留下来的完整条件、范围控制或“当前”等状态修饰必须继续位于显式义务之前，不能因主语省略被误删。条件、角色范围、关系参与者、数字正负号、单位、字面值、英文标识和新增业务含义必须仍有同一引文依据。字段重排只在同一结构明确的集合内成立，不得把输入集合成员迁移为输出集合成员；枚举标点只证明成员边界，每个可重排成员还必须由成对引号或逐成员布尔语法证明为字段，且成对引号内部的集合分隔字符保持为标签正文，不使用字数阈值、有限动词词尾或业务字段词典。多条 quote 或逗号分隔的不同从句不能拼成一条原文没有表达的事实，无法确定证明时保持失败关闭。该规则不引入项目动作词典，也不把 KEE 结构通过等同于 Java 业务通过。

直接依据拒绝的规则级诊断复用 V14 已有三列而不新增迁移：公共 code/path 保持不变，内部 `validation_error_message` 只允许“固定公共说明 + 固定枚举集合”的严格存储形式。读取详情时先验证存储形式，再只投影固定公共说明；普通日志同样不记录规则集合。规则分析在单条引文内完成，多引文先检查是否存在支持项，全部失败时才按枚举声明顺序形成有界去重集合。该集合只说明确定性校验在哪一层失败，不代表语义裁决，也不得触发自动放宽或重试。旧记录只有固定公共说明时继续兼容。显式恢复必须在现有事务锁内读取 task、每个目标 work 及其最新失败 attempt 的完整 code/path/message 三元组，逐层使用同一个严格解析器校验，并要求三层规范表示完全一致；未知、重复、乱序、混入任意原文或凭据、任一层不完整或不一致均失败关闭。内部原因集合只用于安全诊断，不扩大可重试错误类型，解析失败不得把数据库原值保留到异常 cause、日志或公共 API。

直接依据误拒恢复以失败窗口为最小变更集。同一功能已原子完成的零事实、零反馈窗口及其发布账本保持不变；任何保留的已完成事实或用例工作都必须重新证明 accepted hash 与对应发布投影闭合，不能只凭工作状态跳过执行。全部已完成事实窗口的公开结果会形成任务级事实键与引文哈希并集，并与持久化集合精确比较，避免逐窗口子集校验漏过额外行，同时允许同一稳定事实跨窗口合法合并引文。恢复只在当前固定 work 批次装载完整功能文字、事实、引文、反馈、测试点、三态、用例、步骤、绑定、解析单元正文和 V23 回放 JSON；批次结束即释放，任务级快照只保留工作元数据、发布哈希、集合身份和闭合布尔值。失败窗口必须具有非空且属于冻结已审核范围的功能身份。V2 任务先在锁内选择 V2 专用恢复，不能因同任务存在旧批次行而先改变旧状态。V23 在发布账本中仅增加通过 Java 校验的公开 V2 结果，不保存 KEE 外层响应、提示词、凭据或诊断正文；恢复时从冻结输入重新运行同一个生产验证器，并把结果与事实、反馈、测试点、三态、用例、步骤和绑定逐项闭合。历史发布若没有可复演公开结果，只能走能够从既有投影精确重建的缺事实回退，否则失败关闭。

### 4. 用例按一个测试点生成并保持三态一致

Java 每次调用只传一个已持久化测试点及其有依据的事实。`generated`、`pending_only`、`unable_to_generate` 与用例数量、用例状态和缺失信息严格闭合；正式用例必须有事实键和证据闭包，待确认用例必须保留缺失信息，无法生成只保存结果与反馈而不伪造用例。

每个测试点的结果、用例、步骤、绑定和结果哈希在同一事务提交。单点失败不回滚已完成点，也不把任务错误标成覆盖完成。

稳定用例键覆盖所有可发布执行字段，包括初始化、输入、步骤、逐步预期/评价、总体评价、异常终止、结果采集、事实与证据集合；同名同标题但执行内容不同的合法场景必须保留为不同用例。

`steps[].expected` 描述每一步的可观察结果，`expected_results` 描述整条用例执行后的总体预期；二者属于不同层级。Java 继续要求步骤编号从 1 连续递增，并分别校验逐步预期和总体预期的非空、长度、读者安全、业务依据、事实与证据闭包，但不得要求总体预期与步骤数量相等或逐项复制步骤文字。历史 V1 合同和只读投影保持原语义，不因 V2 修复而改写。

用例 `name` 与 `title` 是当前测试点的读者身份标签，不是新增执行需求。Java 对这两个字段使用独立的有限组合校验：只消费当前已审核功能名称、功能路径末级、当前测试点描述、所选正式事实/引文以及固定通用测试包装语；候选可使用单条事实或引文内部的连续短语，或按完整片段组合当前功能、测试点与最多一条事实/引文，不得跨多条事实/引文拼成新的业务结论；功能描述不进入该支持集合。其余执行字段继续只使用所选正式事实和连续引文的支持集合，不能因身份标签合法而放宽角色、环境、接口、阈值、状态、错误码或结果依据。正式用例仍只能来自正式测试点，待确认描述不得反向支撑正式候选。

若旧 V2 validator 仅因这一错误等值规则拒绝用例设计，显式恢复只允许处理同一任务内零接收的 `FUNCTIONAL_TESTCASE_DESIGN_V2` 工作：每个 work 的失败历史只允许“零个或多个更早的 `TESTCASE_EXPECTED_ORDER_INVALID / expected_results` 误拒前缀 + 一个或多个 `TESTCASE_UNSUPPORTED_BUSINESS_DETAIL / name|title` 身份误拒后缀”，两段均须为连续 `business_validation_failed` 终态且不得倒序、交错或混入第三类错误，最新 attempt 必须与当前 work 诊断一致；失败 work 的 coverage status 必须为空，且不得有 accepted hash、租约、运行 attempt、用例、步骤、绑定、生成结果或发布账本；已完成事实 work 及其事实、引文、反馈和发布账本保持不变。恢复只重排未完成设计 work；下一次协调执行按稳定身份跳过已完成事实，不得重新调用事实 Skill。

历史身份标签误拒使用另一条严格恢复分支，不能借用总体预期或技术故障白名单。事务在固定锁序下要求 V2 `PARTIAL/FAILED/UNABLE_TO_GENERATE`、当前制品 ID/SHA/路径唯一归属、全部未完成工作均为零写入设计工作，且历史 attempt 只符合上一段冻结的“连续旧总体预期误拒前缀 + 连续身份误拒后缀”顺序，并证明没有测试点结果、用例、步骤、绑定或设计发布账本。工作图允许保留由同一已审核功能确定性重建的 `SUPERSEDED` 无事实占位项，但其持久化登记坐标必须与规划器重算结果逐项相等，coverage、诊断、accepted hash、租约和业务行必须全空，历史 attempt 只能是连续终态零写入 `failure_type=request_too_large`；恢复时保持该占位项及其 attempt 原样不动。历史终态允许两种精确外壳：已有结果快照且任务诊断三元组全空，或结果快照为空且任务诊断是安全的 `name/title` 误拒并与至少一个失败 work 的最新诊断完全一致；混合、部分或不一致外壳均拒绝。mutation 只重排该完整失败集合并清除当前任务诊断；旧 attempt 和磁盘制品文件不删除，失败制品坐标作为同任务待替换版本保留。任务进入执行态后，既有下载门禁必须隐藏该制品；新终态制品只可通过既有原子发布路径替换坐标。已完成事实/反馈/发布账本不变。任何身份漂移、占位项覆盖状态或诊断漂移、额外未完成工作、部分设计发布、租约或并发领取均失败关闭。

### 5. 处理状态与覆盖结果分轴

处理状态描述编排是否结束以及是否存在技术失败；覆盖结果只根据已审核功能范围、正式/待确认/无法生成终态计算。材料质量反馈不会直接令任务技术失败；未完成工作不得伪装为覆盖，PARTIAL 也不得显示为 COMPLETED。

V2 新任务在模型调用前或模型执行阶段发生纯技术故障时，失败收口可能生成一个只描述失败状态的 artifact。显式恢复不能把所有 `PARTIAL` 任务普遍开放，也不能只看公开错误字符串：事务必须按 task → unfinished work → 全部 attempt → 业务表的固定锁序证明只有 V2 work、全部历史 attempt 均连续且以有限技术类型终止、所有 accepted hash/租约/运行 attempt/业务与暂存行均为空，并验证 artifact 标识和路径的唯一身份及 64 位内容摘要。V24 为 artifact 标识和路径摘要建立唯一索引，锁内按固定顺序分别查询，避免不同任务在无索引全表扫描中交叉死锁；内容 SHA 可因工作簿内容相同而重复。mutation 使用 `READ COMMITTED`，先独占父 work 行，再以新的语句视图核对 attempt 历史：父行锁通过外键阻止新增 attempt，后续读取可看见获得父锁前已经提交的历史；调用方若已存在不兼容的旧快照事务则失败关闭。实现同时禁止对 `(work_item_id, attempt_number)` 的前缀范围增加跨 UUID next-key 锁，避免互不相关任务相互等待。Java 新产生的本地请求预算拒绝统一记录为不可恢复的 `invalid_request`；部署前无法区分来源的历史 `request_too_large` 只在完整零写入闭集下兼容显式恢复，若仍是本地超限也只能再次失败且不能发布业务结果。恢复 mutation 只重排同一批失败 work、清除失败 artifact 和当前诊断，保留冻结输入、work 身份与历史 attempt；下一 claim 负责创建新 attempt。业务校验、结构化输出、合同错误、不可缩小容量错误和旧 V1 路径继续失败关闭。

### 6. V20 采用追加式 V2 数据模型

新增 V2 表保存已审核功能范围、事实、事实引文、可测性反馈、测试点生成结果和窗口/测试点发布账本，并在任务/制品上保存版本字段。迁移只新增可空兼容列和新表/约束，不删除或改写 V14-V19。所有业务唯一约束同时包含 task、版本化范围和稳定业务键。

### 7. 同源 API、页面与 Excel

详情 API 以持久化版本选择 V1/V2 投影，不返回原始 KEE JSON、内部枚举键或凭据。V2 页面用中文展示处理/覆盖双轴、反馈、正式和待确认结果。Excel 仍恰好两张 Sheet：V2 第一张固定为 `需求可测性反馈`，展示非阻断反馈与缺失信息；第二张固定为 `测试用例` 且只展示正式测试用例。V1 历史任务和历史制品继续保留旧名称 `需求与功能清单审查发现`，不得因 V2 导出而重建或改名。两张表均从同一 artifact 所绑定的已提交数据生成并进行公式注入防护。

本轮发布验收不执行浏览器页面级检查，页面仍属于产品交付范围，但视觉、按钮交互和浏览器兼容性不得据此声明通过。验收只采用四层证据：用户态详情/下载 API；数据库只读快照与 API 的状态、计数和追踪关系对账；同一 artifact 的 Excel 程序回读；前端单元测试、类型检查、ESLint/静态检查和生产构建。证据必须明确记录浏览器验证未执行，不能用 API 或构建结果替代页面级结论。

V2 详情按服务端页加载：可测性反馈、测试点和测试用例使用独立页码，每次只返回一条可能接近 4 MiB 的用例及其步骤和需求摘要；有真实结果时不得同时显示空状态。V2 Excel 使用 MySQL Connector/J 驱动级流式游标、单向数据库行源与 SXSSF 固定窗口写入，每类数据一次主查询并在结束后复核计数，禁止驱动预取全量结果、OFFSET 反复扫描或按行查询步骤/证据。缺失信息按规范文字排序去重，不能继承 JSON 聚合或物理插入顺序。先生成未发布临时文件，完成行数闭合、两张 Sheet 和表头校验后再原子发布；历史 V1 制品仅保留读取兼容。

单个测试点和单条已接收用例都可接近 4 MiB，因此详情固定每页一个测试点、每页一条用例，反馈仍可使用轻量页大小；RUNNING/PENDING 仅展示阶段进度，连待确认用例计数也不从变动中的集合投影，终态后才开放结果分页。详情中的计数、当前页及关联子项在同一只读可重复读事务快照中组装。

Excel 数据库行源对每类业务数据只执行一条有序流式主查询，查询语句必须启用 MySQL 驱动级逐行读取，步骤和需求摘要在同一行聚合，SXSSF 只保留一个工作簿行窗口。生产行源必须按不向读者暴露的来源身份严格递增；导出器以此同时证明全量顺序和来源去重，少行、多行、重复或乱序均失败关闭。文件系统不支持原子移动时不得降级为普通移动，临时文件必须清理且制品不得发布。

## Risks / Trade-offs

- [受保护脏工作树包含旧路线代码] → 新增独立 V2 类型和版本分派，严格控制变更文件，不重构或删除旧实现。
- [稳定事实键规范化不一致导致重复或冲突] → 把规范化/哈希作为单一纯函数，用固定向量、顺序变化和并发幂等测试锁定。
- [窗口成功但事务中途失败造成部分正式数据] → 先校验后写入，使用单事务账本和唯一约束，并用真实 MySQL rollback/并发测试证明。
- [材料质量差导致全部无法生成] → 零事实、待确认和无法生成均为可持久化终态；其他函数/窗口/测试点继续。
- [前端或 Excel把待确认计入正式覆盖] → 以服务端同源投影和精确计数测试锁定，第二 Sheet仅查询正式用例。
- [历史任务受新字段影响] → 新列可空，版本缺失走 V1 只读适配；迁移与历史详情/下载回归使用已有数据夹具验证。
- [请求在进入 KEE 前被本地大小策略误截断] → 序列化完整请求后测字节，超限失败关闭；不得截断 unit content 或拆成互不知情的内容。
- [超长材料或大用例在15个并发读取/导出时耗尽堆] → 解析单元逐页暂存、详情单测试点分页、Excel单业务行分页和单行SXSSF窗口；所有入口按计数与来源身份闭合。

## Migration Plan

1. 先合入 V2 DTO、纯校验器和 RED/GREEN 合成测试，不切换运行路径。
2. 应用 V20 向前迁移并用 Testcontainers 验证新装、V19升级、约束、回滚和历史读取。
3. 接入版本化 V2 协调器与事务仓库，新创建路径冻结 V2，历史路径只读保持。
4. 接入 API、页面和 Excel 同源投影，完成前后端及工作簿回读门禁。
5. 在 KEE 主会话复核和部署放行前停止；本 change 不执行 Java 部署或真实任务。

回滚只回退 Java 运行物；V20 结构保留，不删除数据。由于新任务尚未运行，回滚时不会把 V2 任务降级为 V1。
