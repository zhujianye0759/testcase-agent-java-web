## Why

The generation workflow is functionally complete, but the configured KEE agent still produces uneven executable detail and the current Web interface does not communicate the product's intelligence, reliability, or task progress at the quality expected for a shared testing platform. This change tightens the non-code generation guidance and gives the complete PC workflow a coherent, high-quality technology visual language without changing the established Markdown, two-sheet Excel, scope, or task APIs.

## What Changes

- Tighten the existing KEE API agent prompt so steps and expected results are one-to-one, negative coverage is concrete, wording is observable, test data is explicit, view operations are granular, and audit findings stay evidence-bounded.
- Improve the configured Good/Bad example documents so AUTO examples demonstrate the tightened output quality while remaining method-only references and never formal requirement evidence.
- Redesign the application shell, creation page, task list, and task detail as one coherent, modern technology-oriented PC experience using semantic tokens rather than scattered visual literals.
- Refine the first visual implementation into a more distinctive, restrained control-deck experience: richer shell/surface hierarchy, controlled technical ambience, and stronger primary-action focus without changing any business workflow.
- Preserve the current business workflow, REST contracts, strict knowledge scope, fixed Markdown tables, two accumulated Excel worksheets, shared operations, and accessible Chinese wording.
- Add regression and browser acceptance coverage for loading, ready, empty, no-results, error, keyboard focus, duplicate-submit prevention, and 1024×768, 1440×820, and 1920×1080 viewports.

## Capabilities

### New Capabilities

- `agent-guidance-quality`: Covers the configured KEE prompt and Good/Bad example quality rules used by AUTO generation.
- `technology-web-experience`: Covers the visual system, page hierarchy, application states, accessibility, and responsive PC acceptance of the generation workflow.

### Modified Capabilities

None. The existing generation, scope, Markdown, task, and Excel contracts remain unchanged.

## Impact

- KEE runtime configuration: the existing API agent system prompt and two whitelisted example documents, updated only through supported KEE configuration/document APIs or UI.
- Java Web repository: Vue views, shared application shell, semantic CSS tokens/styles, frontend tests, browser acceptance script, and UI decision documentation.
- No KEE Go source change, Java backend API change, database migration, new frontend dependency, login/permission feature, or output-contract change is planned.
